description: Stage, commit, and push changes with a conventional commit message
---

Review the current git status and diff, verify the change is clean, then stage it, write a concise Conventional Commit message, commit, and push to the current branch.

## Steps

1. **Check status**: `git status` to understand what has changed
2. **Review the diff**: `git diff` (and `git diff --cached` if anything is already staged). Read the actual changes, not just filenames
3. **Verify before committing** (the same checks AGENTS.md requires):
   - `gofmt -l .` must print nothing
   - `go vet ./...`
   - `golangci-lint run ./...` must report 0 issues
   - `go test -race ./...`

   If anything fails, stop and report it instead of committing
4. **Stage**: `git add -A`. Never stage build artifacts (the `gopyter` binary, `*.ipynb.tmp`) or scratch notebooks outside `examples/`
5. **Craft the commit message** following Conventional Commits:
   - Format: `<type>(<scope>): <short summary>`
   - Types: `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `perf`, `build`
   - Scope: optional, the package affected: `ui`, `kernel`, `complete`, `lsp`, `notebook`, `runner`, `cmd` (for `main.go`)
   - Summary: imperative mood, lowercase, no trailing period, ≤72 chars
   - Body: a blank line, then bullet points explaining *what* and *why* for non-trivial changes
   - Reference issues with `(#N)` in the subject and `Fixes #N` in the body when applicable
   - Do **not** include "Generated by" or similar noise
6. **Commit**: `git commit -F -` with a heredoc, so multi-line bodies survive intact
7. **Push**: `git push` (use `git push -u origin "$(git branch --show-current)"` if the branch has no upstream)

## Guidelines

- Read the actual diff; do not guess from filenames alone
- Prefer one well-scoped commit. Split only when the changes are clearly unrelated (e.g. a bug fix plus new docs), and then commit each part separately
- Keep the subject line under 72 characters
- If there is nothing to commit, say so and stop
